## III. Boundary Rules — The Law

### Rule 1: Exposure Hierarchy
Public surfaces must be constructed in ascending order of exposure isolation:
```
LinkedIn (highest exposure, most filtered) 
  → Newsletter (subscriber-only, trusted audience)
  → Landing Page (SEO public, carefully curated)
  → Manifesto (authoritative public canon)
  → C4 Diagrams (architectural abstractions)
  → SPR Definitions (responsibility boundaries)
  → Gate Assignments (governance only)
  ↓
Protected Machinery (zero public exposure)
```

### Rule 2: Protected Machinery Reference
- ✅ **Allowed:** "Our wasm4pm algorithm optimizes X using principle Y"
- ✅ **Allowed:** "Prompt Manufactory uses LLM-guided research to generate Z"
- ❌ **Forbidden:** Actual algorithm code, prompt templates, internal logic
- ❌ **Forbidden:** Performance comparisons with competitive implementations
- ❌ **Forbidden:** Type system internals or constraint solving details

### Rule 3: Teaching vs. Implementation
- **Teaching documents are public:** Nehemiah framework, design patterns, gate theology, 52-day discipline
- **Implementation is protected:** Specific algorithms, internal data structures, optimization tricks
- **Corollary:** You can teach "how to think" but not "how we specifically do it"

### Rule 4: Receipt Lifecycle
- **Phase 1 (Internal):** Receipts issued to team only; format protected
- **Phase 2 (Announced):** Public announcement of receipt existence and purpose
- **Phase 3 (Published):** Receipt schema and validation logic made public
- **Timing:** Publication timing is separate from issuance; never leak ahead of schedule

### Rule 5: Data Sanitization
Before any public artifact:
1. Remove implementation code patterns
2. Remove specific performance numbers (if competitive)
3. Remove internal API details
4. Remove deployment/infrastructure specifics
5. Replace with conceptual equivalents or abstraction layers

### Rule 6: LinkedIn Growth Metrics
- ✅ **Public:** Daily post count, engagement rate, subscriber growth
- ✅ **Public:** Completed wall sections, Nehemiah progress
- ❌ **Protected:** Internal conversion funnels, private audience metrics
- ❌ **Protected:** Non-public research data or unpublished doctrinal content

### Rule 7: Wall Completion as Proof
- **Public metric:** Physical wall sections (LinkedIn posts, completed gates)
- **Proof:** Documented progression through Nehemiah 52 (Fish Gate → Water Gate → Dung Gate)
- **Protected:** Internal resource allocation, private research timelines

### Rule 8: Competitive Moat
The following create our competitive advantage and must remain protected:
- Wasm4pm algorithm specifics
- Ggen template rendering logic
- Prompt Manufactory warrant generation
- Type law optimization details
- Internal receipt validation

Public teaching can reference these concepts but must not expose implementation.
